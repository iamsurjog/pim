## System Architecture & Feature Specification

A unified, high-performance toolchain written in Go designed to orchestrate Python runtimes and manage dependencies using dynamic runtime injection. This architecture completely eliminates traditional virtual environment folders, bypasses cross-drive filesystem boundaries, and delivers single-digit millisecond CLI execution.

---

## 🏗️ Core Architectural Pillars

### 1. Zero-Disk-Waste Global Cache

* **Mechanism:** Packages are downloaded, unzipped, and stored exactly *once* in a structured global cache directory localized to each physical drive (e.g., `C:\.package-cache\`, `D:\.package-cache\`).
* **Storage Layout:**
```text
.package-cache/
└── <package_name>/
    └── <version>/
        ├── site-packages/   # Direct Python module source code
        └── bin/             # Native executable shims (e.g., jupyter)

```


* **Isolation:** Isolating installations strictly by package name and specific version subdirectories ensures absolute version compliance and prevents namespace/version collisions across different projects.

### 2. Pristine Project Spaces (No `.venv` Directories)

* **The Concept:** Project directories remain completely clean of dependency code or heavy binary copies.
* **The IDE Bridge:** To ensure Language Server Protocols (LSPs like Pyright/Pylance) provide full autocompletion and diagnostic testing without showing missing import errors, the Go tool automatically drops a local, lightweight `.env` file into the project root:
```ini
# Generated by tool - Do not commit
PYTHONPATH="D:/.package-cache/requests/2.31.0/site-packages;C:/.package-cache/numpy/1.26.0/site-packages"

```



### 3. Dynamic `PYTHONPATH` Injection Engine

* **Execution:** Instead of utilizing filesystem linking (like symlinks or hardlinks) which break compiled C-extensions or fail across multiple physical drives, the Go orchestrator builds the environment dynamically at runtime.
* **Process Handoff:** Go reads the target project requirements, constructs a single cohesive path string containing all relevant cache locations separated by the OS-specific delimiter (`:` on Unix, `;` on Windows), appends it to the `PYTHONPATH` environment array, and launches the host Python interpreter using native `os/exec` handoffs.

## 🛠️ Feature Breakdown

### 🎯 Feature 1: Multi-Version Python Management

* **Behavior:** Switch between underlying system Python interpreters instantly via project configuration.
* **Implementation:** The Go binary tracks available local Python installation paths. Because there are no `.venv` folders to rebuild or wipe when switching versions, changing the target version in your configuration causes the Go engine to point to the new Python executable path on the very next run command instantly (taking less than 2 milliseconds).

### 📦 Feature 2: High-Performance Package & Script Runner

* **Configuration Layer (`your_tool.toml`):** Takes core structural inspiration from modern package tracking protocols (like `package.json` or `pyproject.toml`) to store manifest details and run scripts:
```toml
[project]
name = "my-app"
python = "3.12"

[dependencies]
requests = "^2.31.0"

[scripts]
start = "python main.py"
test = "pytest tests/"

```


* **Concurrency Engine:** Built natively using Go channels and goroutines to handle multiple wheels simultaneously, downloading and unzipping packages at absolute network and storage device hardware thresholds.

### 🧹 Feature 3: AST-Driven Automated Dependency Tidy (`go mod tidy` Style)

* **Behavior:** Cleans up or automatically adds dependencies directly based on actual codebase utilization.
* **Mechanism:** The tool scans project source files to look for explicit `import` and `from ... import` declarations using a static analysis parser. It calculates matching packages against PyPI registries, automatically downloading missing utilities to the global cache and logging them into the manifest file.

### 🏃 Feature 4: Zero-Hassle Script Execution (`pip-run` Functionality)

* **Behavior:** Run any standalone Python script instantly without manual configuration files or pre-configured environments.
* **Mechanism:** Typing `your-tool run script.py` triggers an instantaneous AST analysis of `script.py`, fetches any required dependencies directly to the global cache if they aren't already present, compiles the paths, and fires up the script via path injection automatically.

## 🚧 Critical Development Edge Cases to Track

* **Windows vs. Unix Delimiters:** Ensure path joining logic handles `runtime.GOOS` constraints dynamically (`:` for Unix environments, `;` for Windows environments).
* **Package Bin Executables:** Tools like `jupyter` look inside the wheels' `entry_points.txt` metadata file to expose binaries. The Go CLI must explicitly look into the cached package's `bin/` or `Scripts/` subdirectory and run them using Python execution hooks when invoked.
* **Module-to-PyPI Naming Discrepancies:** Account for standard packaging variations where an internal module declaration doesn't perfectly match its PyPI distribution identity (e.g., `import yaml` relies on downloading `PyYAML`).
